# 指定範圍驗證

GitHub Actions → CI → Run workflow 可選 `ui_scope`。`full` 保留完整驗證；
`memory`、`sliding` 等選項只執行該遊戲與直接相關的 UI 路徑，仍會真實編譯並執行 App。
局部結果會保留日誌、原始截圖與實際 XCTest summary，不能當成所有遊戲都重跑通過。

日常修正先跑受影響範圍。遊戲程式、共用元件、題庫或存檔改變時，發布前仍需一次完整整合驗證。
這與每次微小修正都重跑三套完整 UI 不同。

另提供嚴格限制的測試工具修復模式：只有 App、Core、資源、工程、Bootstrap、套件與簽署程式
完全未改，且所有測試方法與斷言未改，才允許引用上一輪完整 CI 的已通過案例。
原失敗項目必須在新一輪指定測試中實際通過，證據逐項記錄來源 Run；缺項、額外失敗、
非預期略過或任何遊戲程式變動都會拒絕發布。`baseline_run` 僅供這種模式使用，
不是一般跳過測試的開關。

TestFlight 仍由主分支的受信任手動入口及既有 match readonly 簽署流程執行；
上述選擇性 UI 工作不讀取 Apple 金鑰、不建立憑證，也不自動發布 App。
