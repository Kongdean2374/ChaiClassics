# ChaiClassics 0.3.0

開發分支：`develop/0.3.0`；已驗收基準：`e670922`（0.2.2）。本版補齊目錄中其餘 17 款遊戲，合計 25 款。依使用者 11 月 18 日最新指示，本次先以基本程式／核心規則／存檔檢查送 TestFlight，介面與手感交由實機測試；不以未完成的完整 UI 測試阻擋測試版。

## 範圍

- 邏輯與拼圖：數織、數和、華容道。
- 棋類：五子棋、黑白棋、象棋、暗棋、西洋棋、將棋；離線 AI／同機雙人。
- 接龍：經典接龍、蜘蛛接龍、新接龍、金字塔接龍、三峰接龍。
- 街機：貪吃蛇、落塊拼圖、打磚塊。

全部使用既有對局結算／暫停、單遊戲設定、搜尋及篩選紀錄、匯入匯出、雙語、主題與美術材料。每款規則獨立，既有八款的存檔 namespace／payload、Bundle ID、150 題數獨與簽署資產不變。

## 驗收記錄

本次 TestFlight 採明確的 `validation_mode: beta` 與 `--manual-qa`：保留 main／候選 tag／來源 SHA／版本的檢查，保留所有 71 項 UI 案例及 26 條對局／歷史路徑；尚未執行或未通過者明確記為待實機驗證，不生成假的成功紀錄。

Run `44230785877` 的 223 項 Swift 核心測試、150 題數獨與存檔相容檢查、真正 iOS Simulator App build 已通過，工具／YAML／fastlane 檢查亦通過。這些是同一 App／Core 原始碼的基本結果，不代表全部 UI 通過。依最新 [開發策略](DEVELOPMENT_POLICY.md)，取消多餘的完整 UI 分組；後續只修改 CI／Beta 入口與對應測試文件，不修改遊戲。

基本驗證後整合 main，Codex 主動觸發 TestFlight，檢查上傳與 Apple 接收／處理狀態並回報。Beta 不等待完整 UI，正式 `full` 模式仍可使用，App Store preparation 明確要求完整 UI；不自動提交 App Store，不修改憑證。實機優先驗證續玩滑動／刪除確認、全部新遊戲操作、歷史搜尋收鍵盤、動畫手感與升級後保存進度；後續依實際 bug 回報做針對性回歸。

以下為先前完整自動化驗證的開發紀錄，並非本次測試版的等待門檻。

## 共用確認與續玩手勢修正

0.2.2 實機回報：滑動續玩列有時同時觸發續玩；左滑刪除先讓列消失，確認框的兩個按鈕可能無反應。0.3.0 改為一般紅色 swipe action，禁止原生 destructive 的預先移除；確認視窗在自身生命週期內持有一次性回應狀態，不捕捉父列尚未建立的 token。背景在通知開啟時停止接受輸入。以原生 UIKit 觸控觀察器隔離拖曳、取消、反向滑動與多指觸控，不攔截系統捲動或左滑功能。

所有遊戲遵循同一規則：滑動不續玩、不刪除；點選刪除僅顯示確認；取消後進度與歷史不變，重開 App 仍能繼續；只有確認才刪除該遊戲的目前進度。新局覆蓋、清除與匯入取代也只在確認後提交。保留重複點擊與過期回應的防護。新增觸控狀態測試，原八款 UI 對局路徑增加左右滑誤觸檢查，以及取消刪除後重啟 App 的保存驗證。實際 iOS UI 結果待補。

已實作 17 款規則引擎、雙語遊戲畫面、25 款目錄與新增插畫；新遊戲接入既有的對局／設定／存檔及備份架構。第一輪新增的 36 項核心測試通過，包括唯一解、棋類特殊規則、八方向翻子、暗棋資訊隔離、五款接龍、街機碰撞、資料隔離及舊備份相容。全套 214 項第一次回歸中的競態測試仍寫死八款遊戲的工作數，已修正為每款八次並另行重跑；此處不代表最終候選或 iOS 畫面驗證已通過。

## 第二階段：操作回歸與發布門檻

補上 17 份由真實 Core 驗證可合法結算的固定 UI 種子；僅放入測試 bundle，不放入正式 App。每款 UI 路徑涵蓋原生左右滑、取消與確認刪除、程序重開、暫停／退出／繼續、實際完成或失敗、結果回看、歷史、取消覆蓋及建立新局。六款新棋類另外操作新棋局並等待真實離線 AI 回應。

貪吃蛇與落塊開始／恢復時先倒數三秒；將棋持駒列可水平捲動；接龍歷史依實際抽牌／花色模式記錄難度。暗棋另外修正共用棋子 ID 與暗棋等級不同的車馬比較，困難 AI 評估公開棋子的回吃風險，仍不讀暗面身分。

221 項完整 Swift 測試已在 Linux 通過；其後新增的暗棋規則及 AI 測試另外驗證。249 項 Python 檢查、Ruby workflow/YAML、原 150 題唯一解與不可變題庫相容檢查通過。這些結果不代表 iOS UI／TF 已通過。

上一輪 Actions 的 Swift 規則與 App build 通過，但 UI bundle 因測試輔助程式變數作用域錯誤未編譯；已修正。工具測試的舊版目錄與來源雜湊契約也已逐項更新。下一輪實際 iPhone／iPad 結果待補，不引用失敗 Run 作為發布證據。

0.3.x 要求完整候選證據，明確拒絕舊 0.2.x 手動 QA 模式。保留全部既有 UI 斷言，新增到 67 個案例、26 條必要對局／歷史路徑；可分組與依相依來源重跑。簽署與上傳 job、憑證及 Secrets 不變。

## 已確認的 Intel 效能回歸

`c0da132` 的 CI 分組 A 在 Intel 的舊井字棋 `testHardOpeningPerformanceIsBounded` 實測 5.154 秒，超過原有 5 秒門檻；50 組種子難度測試耗時 288.750 秒。取消單一慢速 Run 取得日誌後確認，原因是完整 minimax 重複探索同一盤面，並非 Apple 或簽署問題。

井字棋現使用每次搜尋獨立的精確盤面暫存，保留原有完整搜尋、勝負評分、種子排序與同分選擇。不新增或變更任何存檔欄位、不調寬效能門檻。Linux 的全部 13 項井字棋測試 2.329 秒通過，其中新增獨立 bitboard oracle 核對 5,478 個合法盤面、4,520 個未結束盤面的最佳選擇。Intel 修正後結果及最終完整候選證據仍待下一輪 Actions。

## 棋盤渲染效能修正

使用同一份合法將棋持駒 UI 種子量測，81 次 `outcome` 檢查在 Linux debug Core 約需 0.702 秒。原畫面對每一格各自查詢相同的可操作／勝負狀態，會在這類局面反覆進行合法走法搜尋。棋盤現於一次渲染先取得共用狀態，再傳入各格；持駒列同樣只查詢一次。不快取跨回合結果、不改規則、存檔或合法目標。每格的識別碼、按鈕條件與操作路徑保留。實際 iOS 效果仍由指定將棋與完整 UI 測試驗證，不以這份 CPU 量測宣稱真機 FPS。

## 棋類操作與陣營識別修正

操作邏輯審查確認：黑白棋點到既有棋子時，原先會落入一般棋類的選子路徑；黑白棋以正值 1／2 表示雙方，因此黑棋回合的既有棋子被誤選後，所有落子目標都會被清空。現將五子棋／黑白棋固定為落子模式，既有棋子不可選取，無效點擊不會遮蔽合法空格。既有黑白棋完整 UI 案例增加真實的「點既有棋子 → 合法落子 → 等待電腦回應」，再接續原有完整對局／刪除驗證。

暗棋在恢復盤面後顯示當前紅／黑陣營；同機雙人的棋子朝向依首次翻牌後的玩家歸屬決定，修正玩家一取得黑方時朝向顛倒的情況。棋子無障礙標籤也包含陣營資訊。既有暗棋 UI 方法增加黑方先手的鏡像合法局面及實際吃將驗證，原紅方完整路徑保留。鏡像資料已透過真實 Core 驗證可合法載入、操作並獲勝。

沒有變更測試輔助程式、案例名稱、題庫或存檔格式；UI 仍為 67 項。實際相依性比對仍只有原先 9 項受影響，58 項可在真實通過且來源相符時沿用。新增操作的實際 iPhone／iPad 回歸仍待執行，尚未宣稱 TF 可發布。
